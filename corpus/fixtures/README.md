# Fixtures

Small Oracle dump files with their ground truth. This folder is committed to git.
Large files live in `corpus/work/` and are not committed.

Generated by `corpus/scripts/make_fixtures.sh <ver>`. The SQL that creates the tables is in
`corpus/sql/01_corpus_tables.sql`; the SQL that writes the truth files is `02_truth_fixtures.sql`.

## Do not regenerate casually

Oracle writes timestamps and job identifiers into every dump, so running the export again
produces a different file with the same content. Byte offsets recorded in `docs/formats/` refer
to exactly the files committed here. Verify them with:

    cd corpus/fixtures/18c && sha256sum -c SHA256SUMS

| Service | `XEPDB1` (pluggable database), user `CORPUS` |
| Database character set | AL32UTF8 |
| National character set | AL16UTF16 |
| NLS language / territory | AMERICAN / AMERICA |
| Database time zone | +00:00 |
| Generated | 2026-10-04 (container clock) |
| Tools | `expdp` and `exp` from the same container, version 18.4 |

The authoritative environment record is `truth_env.txt` in the version folder (version, NLS
character sets, language, territory, database time zone). If this table and that file disagree,
the file wins.

## File names

| Pattern | Meaning |
|---|---|
| `<name>_dp_<ver>.dmp` | Data Pump (`expdp`) dump |
| `<name>_exp_<ver>.dmp` | legacy `exp`, conventional path |
| `<name>_exp_direct_<ver>.dmp` | legacy `exp`, `direct=y` |
| `<name>_*_<ver>.log` | log of the export that produced the file |
| `truth_*.txt` | expected values, read from the live database (NULL shown as `<NULL>`, fields separated by `|`) |
| `SHA256SUMS` | checksums of all `.dmp` and `truth_*.txt` files |

`<name>` is a table name, or a group: `multi_framing` (t_frame, t_len, t_nullmix),
`multi_types` (t_num, t_date, t_ts, t_text), `ddl` (t_parent, t_ddl).

## Tables

| Table | Purpose |
|---|---|
| `t_frame` | readable strings (AAAA, BBBB, ...); row framing, NULLs, trailing NULLs; no id column |
| `t_len` | string lengths around 250/251 bytes and others; value starts with `L<length>_` |
| `t_nullmix` | all 8 NULL patterns of NUMBER, VARCHAR2, DATE |
| `t_num`, `t_numtypes` | NUMBER encoding, precision and scale variants |
| `t_float` | BINARY_FLOAT, BINARY_DOUBLE (Data Pump only) |
| `t_date`, `t_ts`, `t_tstz` | DATE, TIMESTAMP(0/6/9), TIMESTAMP WITH (LOCAL) TIME ZONE |
| `t_raw` | RAW values up to 2000 bytes |
| `t_text` | VARCHAR2, CHAR, NVARCHAR2 with multi-byte characters |
| `t_empty` | table without rows |
| `t_wide` | 120 columns, many trailing NULLs |
| `t_parent`, `t_ddl` | constraints, defaults, check, comments, index |

## Known limitations

- **`t_float` has no legacy EXP file.** `exp` refuses the table (`EXP-00104: datatype (BINARY_FLOAT)
  ... is not supported`), so BINARY_FLOAT and BINARY_DOUBLE exist in Data Pump dumps only.
- All fixtures use one character set (AL32UTF8). Other character sets are not covered yet.
- Rows of tables without an id column (`t_frame`) are in insertion order in `truth_*.txt`; the
  dump order is part of what the Analyst checks, not an assumption.
- The data are synthetic. Real corporate dumps never go into this repository.
